# Hodoki

グループの立替と、メンバーごとの負担割合をまとめる共有会計アプリです。

## できること

- グループとメンバーを作成し、URLで共有
- 支払った人、明細、金額、日付を記録
- グループ全体に適用する負担率を設定
- 個別の明細だけ別の負担率に上書き
- 同じメンバーで出かけた回を複数作成し、明細を回ごとに確認
- 回ごとに見ても、グループ全体の累計支出と残高を継続して計算
- 実際に返金・送金した金額を立替明細とは別に記録
- 1円単位で負担額を配分し、端数を自動調整
- 立替額・負担額・記録済み送金から、次に精算する送金先・金額を計算
- 複数人から同時に更新された場合、更新競合を検知

グループのURLを知っている人は内容を閲覧・編集できます。ログインは不要です。共有リンクは会計データへのアクセスキーとして扱い、個人情報などを含む記録は作成しないでください。

## 使い方

1. グループ名とメンバー名を入力して作成します。
2. 「回を追加」で旅行や集まりを登録し、明細を追加するときにその回を選びます。回を選ばずに記録した明細も、全体の累計には含まれます。
3. 「全体の負担率」でグループ全体の割合を設定します。合計が100%になると保存できます。
4. 立替明細を追加し、支払った人、金額、分け方を入力します。通常は全体の割合を使い、特定の明細だけ割合を変える場合は「この明細だけ」を選びます。
5. 明細を回ごとに表示しても、メンバーの残高は全期間の支出を合算して計算します。
6. 「精算のまとめ」の送金案をもとに実際に送金した後、「送金を記録」または「返金を記録」から記録します。送金記録は遊びに使った金額に含まれず、次回の精算額にだけ反映されます。

割合で割り当てた金額の端数は、各明細の合計が元の金額と一致するよう1円単位で配分します。返金記録は実際に送金した後の記録用で、アプリから送金は行いません。

## 開発

Node.js 22.13以降とpnpm 11.25.0を使用します。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

データベースはDrizzle ORMとCloudflare D1を使用します。スキーマを変更した場合は `pnpm db:generate` でマイグレーションを生成します。公開環境への反映はSitesのデプロイ時に行います。

## 技術構成

Next.js互換のVinext、React、TypeScript、Cloudflare Workers、D1、Drizzle ORM。
